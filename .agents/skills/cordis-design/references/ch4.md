# 4. A Calculus of Dynamic Composition

## Summary

Chapter 4 turns the static theory of coeffects and effects from Section 3 into an operational
semantics for a running system that loads, replaces, and unloads components while it executes.
It defines the **component** as a triple of a coeffect specification, a coeffect provision, and a
witnessed effect function, and the **fiber** as a named, stateful instantiation of a component
that moves through a four-state lifecycle (`Inactive`, `Reloading`, `Active`, `Unloading`). A
**registry** tracks fibers by name and derives the ambient coeffect context as the union of what
`Active` fibers currently provide. Nine rules generate two relations: five **orchestration** rules
(only three of consequence: insert, retire, remove) by which an external orchestrator requests a
fiber's existence, and six **lifecycle** rules by which the system moves a fiber toward or away
from a **target view** — the resolution of its dependencies it ought to be running against. A
**confinement** discipline, guaranteed by the syntactic shape of every effect function, bounds
what any rule application can read or write, which is what lets the chapter's metatheory reason
globally from purely local facts. The chapter then proves, at the level of an entire interleaved
system rather than a single component: preservation of registry well-formedness (Theorem 64),
temporal composability in its global form — an accumulator recovers exactly what its fiber
contributed no matter what else has run meanwhile (Theorem 68) — spatial composability in its
global form — a provider never withdraws before every dependent has left, and a transition always
completes against one fixed resolution (Theorems 70–71) — progress (every non-quiescent state can
step, and the system always quiesces, Theorem 73), and confluence (the quiescent state reached is
independent of scheduling and equals what a from-scratch static load would produce, Theorem 80).
Together these results are the formal warrant for treating a dynamically composed Cordis/DSH-like
system as if it had been assembled once, statically, in dependency order — the load-bearing claim
for any host that hot-reloads, replaces, or tears down plugins at runtime.

## Section-by-Section

### 4.1. Components and Fibers

- **Definition 48** fixes a component over context Γ as a dependent triple `ℭΓ ≔ (d : 𝔇Γ) × (p : 𝔓Γ) × ℑ^{d∪p}_Γ`: `d` is the coeffect specification (what it reads), `p ≔ Set(K)` is the coeffect provision (the keys it may install bindings at, and no others), and `e` is a witnessed effect iterator defining the effects the component contributes plus the inverses that withdraw them.
- **Definition 49** defines a fiber as a tuple `⟨d, p, e, π, σ, τ, θ⟩` where `π` is the parent fiber (or the `root` marker), `σ` is the fiber's own coeffect table (empty until activation), `τ` is a monotone retirement flag, and `θ : Θ_Γ ≔ Inactive | Reloading(i, g, ω) | Active(g, ω) | Unloading(g, ω)` is the lifecycle state carrying a remaining effect iterator `i`, an accumulator `g : Γ → Γ`, and a committed view `ω : d → 𝔑` (which key resolves to which providing fiber). A fiber is `installed` exactly when `θ ≠ Inactive`.
- Fiber identity is by atomic name alone: no rule computes, inspects, or compares names except by equality, and instantiation always draws a fresh one — the discipline of dynamically created local names, used here to give every instantiation of a component a distinct, mutation-surviving identity.
- **Definition 50** defines the registry `F_γ : 𝔑 ⇀ 𝔉_Γ` as a finite partial function whose parent pointers form a tree rooted at `root`, and derives the active coeffect context as `σ_γ ≔ ⋃{σ_m | θ_m = Active(–, –)}` — well defined because provisions of distinct fibers are disjoint (enforced by O-Insert), so each bound key has exactly one provider, `provider_k(γ)`.
- No rule ever writes a coeffect table directly; every binding a fiber holds is produced by a provision stage inside its own effect function and removed again by the accumulator, so "a location no key binds is one no fiber touches" — the chapter's basis for later confinement arguments.
- The chapter explicitly departs from Section 3.2.3's realm-scoped resolution by reading every key at one shared realm rather than allowing several providers per key across realms; this simplifies the formalization and pushes multi-provider needs onto realms (Section 4.4) or a broker (Section 6.2) instead.
- **Definition 51** defines `σ^S_γ`, the bindings recorded at a key set `S` across *every* fiber (not only `Active` ones); this is the projection at which the coeffect-context equivalence `γ ≃_S δ` and witnessed-iterator sets `ℑ^S_Γ` are read throughout the chapter, because a binding a transition has written must remain visible to the witness obligation before the fiber becomes `Active`.

### 4.2. The Calculus

- The calculus has nine rules generating two relations: **orchestration rules** (prefixed O-, written `γ ⇒ δ`) are actions an external orchestrator may take, and **lifecycle rules** (prefixed L-, written `γ ⟶ δ`) are steps the system takes unprompted whenever their premises hold; a run is any interleaving of the two, and no rule mentions a scheduler, so a theorem proved over all sequences holds for every scheduling policy.
- Figure 1 draws the fiber lifecycle as a four-node state machine (`Inactive`, `Reloading`, `Active`, `Unloading`) with eight of the nine rules on its edges; **O-Retire** is a self-loop at every node (it only ever sets the retirement flag) and is omitted from the diagram.

#### 4.2.1. Orchestration

- **O-Insert** admits a fresh fiber name `n`, requires its parent to already be present (or `root`), requires the component to be well-typed over Γ, and — crucially — requires that its provision be disjoint from every existing fiber's provision, which is the single-source discipline: a key can have at most one possible provider system-wide.
- **O-Retire** sets `τ_n ↦ ⊤` unconditionally on the fiber's current state, because retiring is only a *request*; carrying it out (deactivating an `Active` fiber first) is left entirely to the lifecycle rules, which prevents leaking a still-active accumulator.
- **O-Remove** requires `τ_n = ⊤`, `θ_n = Inactive`, an empty table `σ_n = ⌀`, and that no other fiber names `n` as parent; these premises keep the parent tree well-formed (children removed before parents) and guarantee a removal discards no un-run accumulator (Corollary 69 depends on this).
- **Definition 52** gives instantiation as the one primitive by which an effect function may create fibers of its own (a plugin loading plugins): an iteration draws a fresh name via O-Insert with itself as parent, and yields as its inverse an O-Retire (not an O-Remove) of that name, because O-Remove carries premises that may not hold when the inverse is finally applied, whereas O-Retire's only premise is presence.
- The vestigial entry an instantiation's inverse leaves behind — retired, `Inactive`, empty table — differs from complete absence only in control fields that no rule inspects (Lemma 62), which is exactly what lets later results treat "removed" and "vestigial" states interchangeably.

#### 4.2.2. Lifecycle

- **Definition 53** defines the target view `target_n(γ)` as `⊥` when the fiber is retired or its dependencies are unsatisfied, otherwise the total map from each declared key to its current provider; a state is `quiet` (quiescent) when every fiber's committed view already equals its target view (or it is correctly `Inactive`), i.e., no transition is in progress.
- Recording a *provider name* rather than a resolved *value* in the target/committed view is deliberate: comparing providers lets the rules detect that the provider changed even when the value it supplies happens to be equal.
- **L-Begin**, **L-Iter**, **L-Finish** drive activation: L-Begin enters `Reloading` when `Inactive` and the target view is defined; L-Iter runs one iteration of the remaining effect iterator, composing its yielded inverse onto the accumulator (`g ∘ h`, last-in-first-out per Definition 18) as long as the target view has not moved; L-Finish lands the last iteration and enters `Active(g, ω)`.
- **Definition 54** defines the guard: fiber `n` is `relied_n(γ)` when some other installed fiber's committed view names `n` for one of its declared keys. This guard is imposed per-binding, not per-fiber, though under the single-source discipline it coincides with a simpler existential test.
- **L-Divert** may take a fiber out of `Reloading` mid-transition (aborting the in-flight iteration, or letting it land, depending on host capability) whenever the target view changes; **L-Leave** moves an `Active` fiber to `Unloading` when its target view changes, without yet running the accumulator; **L-Unload** is the *only* rule that applies the accumulator, and it fires only when the guard `¬relied_n(γ)` holds, discarding the committed view and landing back at `Inactive`.
- The guard is designed not to deadlock: because `σ_γ` unions only `Active` fibers' tables, the moment L-Leave or L-Divert marks a fiber, that fiber's bindings leave the visible coeffect context, so no *new* commitment can name it, and every existing consumer that had committed to it is itself already departing — Theorem 73 turns this observation into a proof that the guard always eventually releases.
- The guard orders deactivations along coeffect dependency, not along the parent/child fiber tree — a parent may run its inverse while a child is still `Unloading`, since `relied` only inspects committed views, not the instantiation tree.

#### 4.2.3. Confinement

- **Definition 55** defines a map `f : Γ → Γ` as confined to `n` when it writes only `σ_n` (fully) and, at another fiber `m`, only the projection `σ_m|_{d_n}` (values at keys `n` declared), and correspondingly reads only `σ_n` and those same restricted projections of other fibers — nothing else, and no control field of any fiber, is legally touched.
- **Definition 56** builds every effect function from exactly three iteration forms — a lifted coeffect operation stage at a key of `d_n ∪ p_n`, a lifted provision stage at a key of `p_n`, or an instantiation (Definition 52) — forming the least such set `ℑ^𝒜_Γ(n)`; every fiber's effect function is required to lie in this set, which is the syntactic form that makes confinement automatic rather than assumed.
- **Lemma 57** proves by induction on this construction that every member of `ℑ^𝒜_Γ(n)` is confined to `n` (instantiation is the one carved-out exception, itself bounded to writing one fresh entry and one `τ`) and lies in the witnessed set `ℑ^{d_n∪p_n}_Γ` that Definition 48 requires of a well-formed component — i.e., the "context paradigm" (build effect functions only from these three stage kinds) is what *guarantees* confinement and witnessing, rather than these being separately checked properties.

### 4.3. Metatheory

- **Definition 58** indexes a run by step `t`, writing `γ_t`, `step_t = r(n)` for "rule `r` applied at fiber `n`," and defines an **episode** of `n` as a maximal interval `[b, u]` throughout which `n` is installed; every step factors as `γ_{t+1} = edit_t(Ψ_t(γ_t))`, splitting each rule application into a state-transforming map `Ψ_t` (an iteration, an accumulator, or identity) and a bracket-edit `edit_t` of named control fields.
- **Table 1** tabulates, for all nine rules, exactly which lifecycle-state transition occurs, which `Ψ_t` is applied, and which control fields are edited — this table is the mechanical basis for nearly every subsequent proof, each proceeding by case analysis over its rows.
- **Lemma 59** collects five structural facts read straight off Table 1 plus confinement: (1) a coeffect table moves only inside a `Ψ_t`, and only at the acting fiber or at keys of a dependent's declaration it holds; (2) a fiber's committed view `ω_n` is constant throughout one episode, created only by L-Begin and destroyed only by L-Unload; (3) the accumulator `g_n` is applied to the state only by L-Unload; (4) a fiber becomes/ceases installed only via L-Begin/L-Unload respectively; (5) `π, d, p, e` are write-once (fixed at fiber creation) and `τ` is monotone (only ever set to `⊤`).
- **Lemma 60** (≃-invariance) shows every rule's applicability and outcome depend on the state only through the coarse equivalence `≃` (agreement on all tables and control fields up to Definition 33's coeffect equivalence), so the whole calculus descends to the quotient `Γ/≃`.
- **Lemma 61** (Equivariance) shows the calculus is invariant under any bijective renaming `χ` of fiber names, justifying that sequences differing only in which fresh names instantiation happened to draw are identified throughout the rest of the chapter.
- **Lemma 62** (Vestigial entries) proves a retired, `Inactive`, empty-table, childless entry is invisible to every rule acting on another fiber, and (with one exception around fresh-name reuse or provision reuse) is interchangeable with the entry's total absence — this licenses treating "retire" and "remove" as equivalent for reasoning purposes.

#### 4.3.1. Preservation

- **Definition 63** defines registry well-formedness by four clauses: (1) every parent pointer resolves in the registry or to `root`; (2) provisions of distinct fibers are pairwise disjoint; (3) an installed fiber's committed view is total on its declaration and valued in the registry; (4) every key an installed fiber's committed view resolves names an installed provider.
- **Theorem 64** (Preservation) proves each rule application preserves all four clauses, by structural case analysis over Table 1; notably clause (3)/(4) preservation hinges on the L-Unload guard `¬relied_n(γ)`, imposed steps earlier for an unrelated reason (deferred withdrawal), which is what prevents O-Remove from ever needing a separate "is anyone still depending on this?" check — removal after `Inactive` is always safe.

#### 4.3.2. Temporal Composability

- **Definition 65** defines iterator independence (lifting Definition 42) and defines two fibers as **entangled** when one's provision meets the other's declaration/provision; a full sequence of steps is **pairwise independent** when every pair of fiber names is either independent or entangled-with-every-shared-key-commutative.
- **Lemma 66** (Pairwise independence) proves *every* sequence of steps satisfies this: a non-entangled pair is independent by Theorem 47 (disjoint keys touched); an entangled pair's shared keys are commutative by construction, since a key's coeffect carries commutativity as its witness (Definition 46) — so the paradigm supplies the independence hypothesis automatically rather than requiring it be checked per system.
- **Lemma 67** (Entangled steps) establishes, for a step acting on an entangled fiber `m` during `n`'s open episode: (1) if `m` provides something `n` depends on, that step's state map is the identity (the guard blocks `m`'s L-Unload for as long as `n` depends on it); (2) otherwise `m`'s step commutes with `n`'s pending accumulator up to `≃_K`; (3) while `n` is still `Reloading`, an entangled `m`'s step is the identity outright (no consumer can yet have committed to a not-yet-`Active` `n`).
- **Theorem 68** (Recovery exactness) is the chapter's headline temporal result: for any episode `[b, u]` of `n`, applying `n`'s accumulator at any point `u` within the episode leaves every table exactly where the same intervening steps (from fibers other than `n`) would have left it starting from `γ_b` — i.e., an accumulator recovers *exactly* the fiber's own contribution, undisturbed by however many other fibers have activated, deactivated, or mutated shared state in between.
- **Corollary 69** (Terminal recovery) specializes Theorem 68 to a *closed* episode: at its end, `γ_{u+1} ≃_K` the state the intervening steps alone would have reached from `γ_b`, and in particular the fiber's own table is again empty — precisely the premise O-Remove needs.

#### 4.3.3. Spatial Composability

- **Theorem 70** (Ordering) proves three things about a fiber `m` that once committed a key `k` to provider `n`: (1) L-Begin only ever fires when the fiber's dependencies are actually satisfied; (2) `n`'s episode strictly contains `m`'s dependent episode (`n` began before `m` and, if `n`'s episode closes, it closes after `m`'s) — i.e., providers outlive their dependents; (3) throughout `m`'s dependent episode, `k` remains bound in `n`'s table and can only be moved by operations at `k` from fibers that actually declare `k`.
- **Theorem 71** (Resolution coherence) proves a `Reloading` episode occupies an initial interval `[b, r]` during which every landing iteration runs against one fixed committed resolution `ω`, and when it leaves that interval exactly one of two things has happened: it finished cleanly into `Active(–, ω)`, or it diverted into `Unloading` and eventually closes with the accumulator recovering exactly what ran (Corollary 69) — so a transition never installs an effect computed against a resolution that has since become stale, except for the one bounded case of a "landing" divert whose safety is exactly what the theorem's second branch guarantees.

#### 4.3.4. Progress

- **Definition 72** defines the precedence relation `n ≺ m ≔ p_n ∩ d_m ≠ ⌀` (n may provide something m declares); the chapter assumes this relation is **acyclic** as an external hypothesis on the set of components (not something derivable), since a component that transitively depends on itself is meaningless.
- **Theorem 73** (Progress) proves, assuming `≺` acyclic, bounded per-fiber iteration length (`len(e_n) ≤ K`), and a finite total name set: (1) **No deadlock** — any non-quiescent state has some lifecycle rule applicable; the proof constructs, from any unblocked `Unloading` fiber, a strictly `≺`-increasing chain of blocking dependents, which must terminate by acyclicity and finiteness, guaranteeing the guard eventually releases; (2) **Termination** — the number of steps acting on any fiber `n` is bounded by `(K+3)(V(n)+1)` where `V(n)` counts target-view changes, and both quantities are finite, so every maximal sequence of lifecycle steps ends in a quiescent state.
- The finiteness of the name set is explicitly *assumed*, not proven, and the chapter names the sufficient condition: no component may instantiate, however indirectly, a fiber of a component that in turn instantiates one of its own without bound (i.e., the instantiation tree has bounded depth and branching).

#### 4.3.5. Confluence

- **Definition 74** defines a fiber as **supported** at a state when it is not retired, its instantiating parent (if any) is supported, and every key it declares is provided by a supported fiber; **Lemma 75** proves this recursive definition is well-founded (given `≺` acyclic) and hence has a unique solution, the support set `A`, depending only on `τ, π, d, p` — none of which change once a fiber is created except `τ`.
- **Definition 76** defines a component as **total on its provision** when a finished activation has installed every key it may provide (not merely some subset) — a condition purely on the components themselves, not on any run.
- **Lemma 77** proves that at a quiescent state, if every component is total on its provision, the support set `A` exactly coincides with the set of currently `Active` fibers — i.e., "ought to be running" and "is running" agree once the system settles.
- **Lemma 78** (Transposition) proves two adjacent steps acting on independent fibers, or one activation step and one orchestration step (that doesn't instantiate the other's target), can be swapped without changing the reachable state — the local commuting-diagram fact that all reordering arguments below build on.
- **Lemma 79** (Deletion) proves that a *closed* episode of `n` whose own instantiated fibers had no episodes, and no `≺`-later fiber's episode closes during it, can be deleted from a run (along with every step on fibers it instantiated) while still reaching the same quiescent state up to `≃_K` — formalizing that a fiber's activation-then-deactivation that fully completes leaves literally no trace.
- **Theorem 80** (Confluence) is the chapter's capstone: given a quiescent terminal state and every component total on its provision, (1) **Canonical form** — that state is reachable, up to names the reduction discards, by a sequence that performs the same orchestration steps in the same order and then runs, for a linearization of the support set `A` by the `⊲`/`≺` order, exactly one episode of each supported fiber, in dependency order, with no closing episodes and no reordering noise; (2) **Confluence proper** — any two runs sharing the same orchestration inputs reach states related (up to renaming) by `≃` and hence `≃_K` — the schedule cannot affect the outcome. This licenses treating a Cordis application's quiescent state exactly as though it had been assembled once, statically, in dependency order, and never torn down.
- The theorem is explicitly scoped to *state*, not to emissions the system produced en route — a distinction the chapter flags as belonging to Section 6.1's acquisition/emission boundary.

### 4.4. Extensions

- **Asynchrony**: the base calculus is synchronous (a step's state map applies atomically). An asynchronous host cannot offer the *aborting* alternative of L-Divert (a future in flight runs to completion regardless), so such a host is **inertial**: it always takes the landing alternative, deactivating only after an in-flight iteration lands. Because every metatheoretic result quantifies over all step sequences and Theorem 73's progress proof never appeals to the aborting alternative, an inertial host still preserves, recovers, and quiesces exactly as the synchronous calculus predicts; an in-flight *deactivation* similarly needs no special treatment because L-Unload is never declined and commutes with later steps by the same machinery Theorem 68 rests on.
- **Failure**: refining the iterator's return type to `Γ → Either(Ξ, Γ × (Γ → Γ) × Maybe(ℑ))` lets an iteration raise an error instead of yielding a triple. A raise exits `Reloading` via an aborting-L-Divert-like route whose target-view premise is dropped (the *iteration* chooses the abort, not the environment), lands `Inactive` having installed nothing (per Corollary 69), and records the error as an outcome that blocks re-entry (L-Begin requires an error-free fiber) without propagating to the parent or affecting sibling fibers. Preservation and recovery hold unchanged; confluence, however, is explicitly broken for failed fibers, because whether an iteration raises depends on the state it happens to meet, so different schedules can leave different fibers failed.
- **Isolation**: extending the shared-realm reading of Section 4.1 to the realm-scoped reading of Section 3.2.3 amounts to reading the whole calculus at the enlarged key set `K × R`: since keys are as atomic to the rules as fiber names (never inspected, only compared for equality), the rules and every Section 4.3 result apply unchanged at `K × R`, with the "one shared realm" case recovered as the diagonal `(k, k)`. The one place this reading stops is `isolate` itself (Definition 25), which reassigns a fiber's realm table at runtime — since `d_n`/`p_n` are write-once (Lemma 59(5)), a realm reassignment is treated as a revision of the fiber's interface rather than something the calculus itself models.
- **Configuration**: the chapter states it gives *four* extensions, and both the Failure and Isolation discussions cross-reference "the Configuration paragraph" (covering revision/reinsertion of a fiber, e.g., a retried failed fiber "starts without an outcome"), but that paragraph's own content falls after the excerpted page range (pages 31–56) and is not present in this chapter's text — its content cannot be summarized from what is available here.

| Fiber | `⟨d, p, e, π, σ, τ, θ⟩` | A named instantiation of a component carrying its own coeffect table, retirement flag, parent pointer, and lifecycle state (Definition 49). |
| Lifecycle state | `Θ_Γ ≔ Inactive \| Reloading(i,g,ω) \| Active(g,ω) \| Unloading(g,ω)` | The four-state machine a fiber occupies; `Reloading`/`Unloading` are in-progress transition states carrying a remaining iterator or accumulator (Definition 49, Figure 1). |

| Coeffect context (registry-derived) | `σ_γ ≔ ⋃{σ_m \| θ_m = Active}` | The active coeffect table: the union of what all `Active` fibers currently provide, well-defined by disjointness of provisions (Definition 50). |
| Key-set projection | `σ^S_γ` | Bindings recorded at key set `S` across *every* fiber, active or not; the projection the witness condition is read at (Definition 51). |
| Provider | `provider_k(γ)` | The unique `Active` fiber name whose table currently binds key `k` (Definition 50). |
| Orchestration rule | `γ ⇒ δ`, prefixed O- | An action the external orchestrator may take (insert, retire, remove) whose premises say when it is legal, not when it occurs (Section 4.2). |
| Lifecycle rule | `γ ⟶ δ`, prefixed L- | A step the system takes unprompted whenever its premises hold (Begin, Iter, Finish, Divert, Leave, Unload) (Section 4.2). |
| Instantiation | — | The primitive by which an iteration of one fiber's effect function creates another fiber, using O-Insert with itself as parent and yielding an O-Retire as the inverse (Definition 52). |
| Target view | `target_n(γ) : d_n → 𝔑` or `⊥` | The resolution `n`'s dependencies *ought* to be running against right now: `⊥` if retired or unsatisfied, else the map from each declared key to its current provider (Definition 53). |
| Committed view | `ω` (inside `θ_n`) | The resolution `n` actually activated against; fixed for the duration of one episode (Lemma 59(2)) and compared against the target view to decide whether a transition is needed. |
| Quiescent | `quiet(γ)` | A state in which every fiber's committed view already equals its target view (or is correctly `Inactive`) — no transition anywhere is in progress (Definition 53). |
| Relied / guard | `relied_n(γ)` | True when some other installed fiber's committed view resolves a key to `n`; L-Unload is blocked while this holds, deferring a provider's withdrawal until its dependents have left (Definition 54). |
| Confinement | — | The discipline bounding an effect function's reads/writes to its own table and the restricted `d_n`-projection of others' tables, and no control field (Definition 55). |
| Context-mediated iterator | `ℑ^𝒜_Γ(n)` | The least set of iterators built only from lifted coeffect-operation stages, lifted provision stages, and instantiations, which every effect function is required to lie in (Definition 56). |
| Episode | `[b, u]` | A maximal interval of steps throughout which a fiber `n` is installed (Definition 58). |
| Well-formed registry | — | Four clauses: valid parent pointers, disjoint provisions, total/valued committed views, and committed views resolving only to installed providers (Definition 63). |
| Entangled fibers | — | Two fibers whose provision meets the other's declaration/provision, `p_m ∩ (d_n ∪ p_n) ≠ ⌀` (Definition 65). |
| Pairwise independence | — | The property that any two fibers' effect functions are either independent or, where entangled, commute at every shared key (Definition 65; guaranteed by Lemma 66). |
| Precedence relation | `n ≺ m ≔ p_n ∩ d_m ≠ ⌀` | "`n` may provide a key `m` declares"; assumed acyclic as a hypothesis on the component set, not derived (Definition 72). |
| Support set | `A` | The recursively defined set of fibers that "ought" to exist: not retired, parent supported, every declared key provided by a supported fiber (Definition 74). |
| Total on its provision | — | A component property: a finished activation installs every key of its provision, not merely some subset (Definition 76). |
| Recovery exactness | Theorem 68 | An accumulator, applied anywhere within its fiber's episode, restores exactly what the intervening steps of *other* fibers alone would have produced — the global form of temporal composability. |
| Ordering | Theorem 70 | A provider's episode strictly contains every dependent episode that resolved a key to it, and that key stays stable throughout — the global form of spatial composability's dependency ordering. |
| Resolution coherence | Theorem 71 | Every iteration of a transition runs against one fixed committed resolution; the only escape is a bounded "landing divert" whose safety the theorem itself proves. |
| Progress | Theorem 73 | Every non-quiescent state has an applicable lifecycle rule, and every maximal run of lifecycle steps terminates at a quiescent state, given `≺` acyclic and bounded iteration/name-set size. |
| Confluence | Theorem 80 | A quiescent state reached by any schedule equals (up to renaming) the one reachable by a canonical, dependency-ordered, never-torn-down "static load" sequence. |
| Realm (isolation extension) | `K × R` | The enlarged key set `(k, r)` used to relax the calculus's one-shared-realm reading to per-realm provision disjointness, without altering any Section 4.3 result (Section 4.4). |
| Inertial host (asynchrony extension) | — | An asynchronous host that can only take the landing alternative of L-Divert, since an in-flight future cannot be aborted (Section 4.4). |

## Relevance to an Agent Harness

- **Plugin load/unload as fiber activation/deactivation**: the four-state lifecycle (`Inactive → Reloading → Active → Unloading → Inactive`) is a direct model for a plugin's install/init/teardown/removal cycle, and the chapter's guarantee (Theorem 68) that an accumulator recovers *exactly* the plugin's own contribution — no matter what else loaded or unloaded meanwhile — is the formal basis for safe hot-reload in a harness with many concurrently active plugins.
- **Dependency injection via coeffect declaration/provision**: a plugin declares what it needs (`d`) and what it exposes (`p`); the single-source discipline (O-Insert's disjointness premise) means a harness enforcing "one provider per capability/service key" gets deterministic dependency resolution for free, and multiple implementations of one capability require an explicit broker or realm-scoping rather than ad hoc multi-registration.
- **Safe teardown ordering**: the guard (`relied_n`, blocking L-Unload) formalizes exactly the rule a harness needs for graceful shutdown — never revoke a shared resource (a connection pool, a config value) while some other loaded plugin still depends on it — and Theorem 70 guarantees this ordering holds transitively and without deadlock (Theorem 73) as long as dependency declarations are acyclic.
- **Reload correctness / confluence**: Theorem 80 is the direct justification for treating "the plugin set currently loaded" as equivalent to "what you'd get from a clean, ordered restart" — this is exactly the property a harness needs to guarantee that live-reload sequences (unload A, load B, replace C, undo the replacement) never leave the system in a state a fresh boot could not also reach.
- **Instantiation as nested plugin loading**: Definition 52's instantiation primitive — a plugin's own effect function may spawn further fibers, whose retirement is entirely automatic when the parent deactivates — models plugins that themselves host sub-plugins or dynamically create workers/sessions, with cascading cleanup guaranteed without the parent needing to enumerate what it created.
- **Bounded reload granularity**: L-Divert's two alternatives (abort mid-iteration vs. let the in-flight iteration land) map to a concrete engineering choice — a harness with synchronous, cancellable install steps can abort cleanly, whereas one built on async operations (network calls, spawned processes) must be "inertial" (Section 4.4) and let in-flight work finish before tearing down; the chapter proves both choices preserve every correctness guarantee.
- **Config reload as revision, not mutation**: because a fiber's declared interface (`d`, `p`) is write-once for its whole lifetime (Lemma 59(5)), the calculus treats any change to what a component depends on or provides — including a realm/isolation reassignment — as retiring the old fiber and inserting a new one, which argues against in-place mutation of a live plugin's contract in a harness implementation.
- **Failure isolation**: the failure extension's design — a fiber that raises an error deactivates cleanly, marks itself failed, blocks its own re-entry, and never propagates the failure to its parent or siblings — is a template for how a harness should contain a single misbehaving plugin's crash without cascading into the rest of the process tree, at the cost of losing the confluence guarantee for that specific run.

## Open Questions and Limitations

- The chapter explicitly restricts to one shared "realm" per key, deferring the more general realm-scoped resolution (letting two fibers provide the same key in different realms) to an extension in Section 4.4 that is stated to only cover the case of realms *fixed at insertion time*; runtime realm reassignment (`isolate`) is explicitly *not* modeled by the calculus itself and is instead treated as an external "revision."
- Finiteness of the total name set `N`, required by Theorem 73 (Progress), is stated as an assumption rather than derived from anything else in the chapter; the chapter only names a sufficient informal condition (no unbounded self-instantiation among components) without formally proving that condition is necessary or that it holds for any particular system.
- Acyclicity of the precedence relation `≺` is likewise assumed as a hypothesis for both Theorem 73 (Progress) and Theorem 80 (Confluence), and the chapter notes plainly that `n ≺ n` can hold for a badly designed component (one that declares a key it also provides), i.e., the calculus offers no internal mechanism to rule this out — it must be checked externally.
- Confluence (Theorem 80) is explicitly stated to require every component be **total on its provision** (Definition 76); the chapter does not characterize what happens under confluence's other hypotheses if a component installs only a strict subset of its declared provision (partial provisioning breaks the support-set argument of Lemma 77).
- The failure extension explicitly gives up confluence: whether an iteration raises depends on the state it happens to meet, so different schedules can leave different fibers failed, and the chapter does not attempt to recover any weaker cross-schedule guarantee for the failure case.
- The chapter states it provides four extensions in Section 4.4, but the fourth — referenced twice in the text as "the Configuration paragraph" (governing revision/reinsertion semantics, e.g., what state a retried failed fiber starts from) — falls outside the excerpted page range (31–56) and its content is not available to summarize here.
- Theorem 68's recovery guarantee is explicitly bounded to what the coeffect keys' equivalences track: a monotone allocator is not "rewound," freed heap layout is not restored, and a sent message stays sent — recovery is only as strong as what the system chooses to reify as a coeffect key, a design decision the chapter defers to Section 6.1.
- The guard's deadlock-freedom argument (inside Theorem 73) depends on the ≺-increasing chain of blocked fibers being finite and non-cyclic; the chapter does not discuss what recourse a host has if a system is misconfigured such that this hypothesis fails at runtime (e.g., a cyclic dependency introduced despite the calculus's acyclicity assumption).
